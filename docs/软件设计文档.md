## 1. 概述

### 1.1 目标与定位

面向内部团队的**小工具聚合平台**：平台只做"底座"（认证、数据库、管理面、部署工程），
具体工具由成员借助 AI 编程按统一规范开发插入。核心设计哲学：**简单、开放源码、AI 可维护**。

### 1.2 设计原则

1. **模块自动发现**：新增工具=复制模板目录+注册一行，禁止修改框架文件
2. **能力复用优先**：通用数据操作（crud.py）、导入导出、鉴权、审计全部公共化
3. **测试即门禁**：打包与升级脚本先跑测试，失败即中止
4. **配置与代码分离**：部署位置/数据库/密钥全部占位符化于 deploy.conf 与 server/.env，不进 Git
5. **跨平台**：Linux（PG+nginx+systemd）与 Windows（SQLite+计划任务+后端托管静态）同一套代码

### 1.3 版本演进摘要

| 版本 | 里程碑 |
|---|---|
| v1.0 | 初始框架（FastAPI+Vue3，模块发现，Docker 部署） |

## 2. 总体架构

### 2.1 部署视图（Linux 生产，172.16.105.2 实例）

```
用户浏览器
   │ HTTP :80
   ▼
nginx（系统服务）─────────────────────────────────────────┐
│ /            → /var/www/super-tools（Vue 构建产物）       │
│               index.html no-cache；assets 一年 immutable │
│ /api/*       → 反代 127.0.0.1:8000（uvicorn）             │
└─────────────────────────────────────────────────────────┘
   ▼
super-tools（systemd 服务，单进程 uvicorn，线程池40）
   FastAPI ── SQLAlchemy ──▶ PostgreSQL 15（127.0.0.1:5432，系统服务）
   可选出站：OAuth IdP（https）、Samba 共享（smbprotocol，445）
```

Windows 形态等价替换：nginx→FastAPI 自托管静态（STATIC_DIR）、systemd→计划任务+自愈循环、
PostgreSQL→SQLite（WAL+busy_timeout）。单机几十并发为设计负载（I/O 密集，单进程余量充足；
扩容路径=uvicorn --workers，应用无状态支持多进程）。

## 3. 关键机制设计

### 3.1 模块自动发现（registry.py）

- 扫描 `modules/` 下含 `__init__.py` 的目录（下划线开头跳过），导入其 `router.py`
- 约定：`router: APIRouter` + `TOOL: dict` 为必需；`models.py` 可选
- `TOOL` 元信息：`title`(菜单名) `icon/desc/usage`(首页卡片) `importable` `tables:{表名:中文名}`
- 路由挂载于 `/api/tools/{模块名}`；`tables` 声明的表自动进入管理面·数据管理
- 单一注册点思想：**框架文件零改动**是扩展性的核心承诺

### 3.2 认证与会话

| 层 | 设计 |
|---|---|
| 本地密码 | PBKDF2-SHA256 十万次加盐；OAuth 自动建号用户写入**不可登录哨兵哈希**（免改列迁移） |
| OAuth 2.0 | 授权码模式（后端机密客户端）；state 一次性（5分钟TTL，用后即删）；PKCE 可选；`AUTH_MODE=local/oauth/mixed` 三模式热切 |
| 会话 | 平台自有 JWT（24h，payload: uid/username/admin/provider）——OAuth 只解决"你是谁"，全部既有 API 鉴权零改动 |
| 账号映射 | `(oauth_provider, oauth_sub)` 唯一索引；首登自动建号；`OAUTH_ADMIN_GROUPS` 声明映射或管理员手工提升 |
| 面板隔离 | 管理面登录带 `panel=admin`：本地/OAuth 两条路径都校验管理员，否则拒签 token |

### 3.3 权限模型

两级角色（admin/business）×三组接口面：

| 接口面 | 鉴权 | 说明 |
|---|---|---|
| `/api/auth/*`、`/api/tools/*` | `get_current_user` | 所有登录用户 |
| `/api/admin/*`（用户/统计/数据管理） | `require_admin` | 仅管理员 |
| 静态资源 | 无（SPA 壳） | 数据与操作全部需 JWT，守卫拦截未认证访问 |

### 3.4 审计与老化

- **访问日志中间件**：每个 `/api/*` 请求记录（时间/用户/方法/路径/状态/耗时/IP），线程池写入不阻塞请求；`access_logs` 表
- **老化**：后台线程每 6h 清理超期访问日志（默认 90 天，`LOG_RETENTION_DAYS`）与遗留 oauth_states（1h）
- Samba 工具另有业务级留痕（见 3.6）

### 3.5 公共数据模块（crud.py）

任意 SQLAlchemy 模型的通用操作，被管理面与工具开发者共同复用：

```
table_columns(model)     列元信息（kind/pk/required/max_length）→ 前端动态表格/表单
list_rows(db,m,skip,limit,keyword)   文本列 contains 搜索，统一 {"total","items"}
create/update/delete_row             写前按列类型 coerce（含明确 400 错误）
import_rows(db,m,rows)   表头=列名，非法行跳过并计数
export_bytes(db,m,fmt)   CSV(BOM防Excel乱码)/XLSX，上限10万行
```

### 3.6 Samba 任务目录（外部系统集成示例）

- **状态真源**：共享目录子目录=任务，存在 `complete.txt` 即完成；数据库只做镜像与流水
  （`samba_tasks` 状态镜像 / `samba_events` 操作事件），两表自动进管理面数据管理
- **连接层**（smbfs.py）：smbprotocol 纯 Python；会话惰性注册、失败自动重置重连；
  UNC 路径仅在连接层拼接，路由只见相对名 → **结构性防目录穿越**；名称白名单二次校验
- **可选依赖**（requirements-samba.txt）：未安装时模块可加载、状态接口给提示（Windows ARM
  无 cryptography 轮子，此环境不装不影响其他功能）

## 4. 数据库设计（共 8 表，PostgreSQL 15 / SQLite 兼容）

| 表 | 字段要点 | 归属 |
|---|---|---|
| users | username唯一；pass_hash(哨兵可空语义)；is_admin；oauth_provider/oauth_sub(唯一索引)；email；display_name | 框架 |
| access_logs | ts/username/method/path/status/duration_ms/ip（ts、username 索引） | 框架 |
| oauth_states | state唯一；verifier(PKCE)；next_path；panel；created_at | 框架 |
| notes / note_categories | 示例工具（单工具双表演示） | 工具 |
| suggestions | username(服务端取)；content(白名单校验) | 工具 |
| samba_tasks / samba_events | 状态镜像 / 操作流水 | 工具 |

迁移策略：无 Alembic，采用**启动轻量迁移**——`create_all` 建新表；`_migrate()` 对既有表
检测缺列后执行方言化 ALTER（加列/唯一索引两种方言均兼容；历史决策：哨兵哈希替代
DROP NOT NULL，规避 SQLite 重建表）。

## 5. 接口设计（REST，JSON）

| 分组 | 端点（代表） | 说明 |
|---|---|---|
| 认证 | POST /api/auth/login（panel 区分面板）；GET /api/auth/me；PUT /api/auth/password | oauth 模式下密码登录 403 |
| OAuth | GET /api/auth/providers；GET /api/auth/oauth/{p}/login?next&panel；GET .../callback | 302 跳转；失败 302 /oauth/done?error= |
| 工具 | GET /api/tools（元信息含 icon/desc/usage/tables）；各工具 /api/tools/{名}/... | 列表统一 {"total","items"} |
| 用户管理 | GET/POST /api/admin/users；PUT .../{id}、/{id}/password（OAuth用户400）、DELETE | 防自删/自降权 |
| 统计 | GET /api/admin/stats | 概览/近14天/工具分布/最近访问/健康 |
| 数据管理 | /api/admin/data/{工具}/{表} CRUD + /import + /export?format=csv|xlsx | 全走 crud.py |

错误约定：业务错误 4xx + `{"detail": "中文原因"}`；外部系统故障 502；导出带
`Content-Disposition`。前端 401 统一由拦截器踢回登录。

## 6. 前端设计

- **技术**：Vue3 + Vite5 + Element Plus；构建产物纯静态（hash 文件名）
- **路由守卫**：登录相关路径一律放行后再判权（杜绝"重定向到相同路径"死循环白屏——踩坑沉淀）
- **动态渲染**：侧边菜单/欢迎首页卡片来自 `/api/tools` 元信息；数据管理页按列元信息渲染动态表格/表单（类型驱动控件）
- **无状态**：登录态 JWT+user 存 localStorage（store.js 持久化），刷新不丢

## 7. 安全设计

| 威胁 | 对策 |
|---|---|
| 密码泄露 | PBKDF2 加盐；不落日志；.env 不进 Git |
| 会话伪造 | JWT 签名（HS256，密钥安装时随机生成）；24h 过期 |
| CSRF（OAuth） | state 一次性+短TTL；secret 仅存后端；PKCE 可选 |
| 开放重定向 | OAuth `next` 仅允许站内路径（`/` 开头且非 `//`） |
| 目录穿越 | Samba 名称白名单正则 + UNC 拼接收敛于连接层 |
| XSS 注入面 | 前端框架默认转义；改进意见内容白名单字符集（连标点都受限） |
| 越权 | 三组接口面依赖注入强制鉴权；管理面登录双重校验（登录时+接口时） |
| 资源滥用 | 上传 50MB 上限（nginx 同步限制）；导出 10 万行上限 |
| 可审计 | access_logs 全接口留痕 + Samba 业务事件流水 |

已知边界（后续加固项）：内网 HTTP 明文（可加自签证书）、无登录限速、无细粒度 RBAC。

## 8. 部署与交付设计

```
开发机                          目标环境（Linux/Windows）
bash deploy/package.sh    →    release/super-tools-vX.Y.Z.tar.gz（含已测代码+预构建前端）
                                    │ 解压
                                    ▼
                     cp deploy/deploy.conf.example deploy/deploy.conf（填 __XXX__ 占位符）
                                     │
                ┌────────────────────┴────────────────────┐
        安装 install.sh（一次性）                  升级 upgrade.sh（可重复）
        系统依赖/建库建号/渲染 systemd+nginx 模板      代码同步(保留venv/.env/数据)→依赖
        注册服务→健康检查；DRY_RUN=1 预检            →测试门禁→前端重建→重启→健康检查
```

- **配置分层**：deploy.conf=部署位置/端口/数据库形态（占位符，安装时校验残留）；
  `server/.env`=运行期密钥（DATABASE_URL/JWT_SECRET/LOG_RETENTION/OAUTH_*/SAMBA_*），由
  安装脚本生成或人工维护，永不入库
- **可选依赖**：requirements-postgres.txt / requirements-samba.txt 按需安装（平台最小化）
- **跨平台脚本**：Windows 为 install-windows.ps1 / upgrade-windows.ps1（读同名 conf）
- 发布包含测试套件，目标机升级即自测

## 10. 已知限制与演进方向

1. 数据库迁移仅覆盖加列场景 → 引入 Alembic（当表结构变更成为常态时）
2. 单进程（负载余量大）→ `--workers N`（架构已无状态，随时可开）
3. 认证限速/锁定、HTTPS、细粒度 RBAC、操作审计报表化
4. 日志解析大文件改后台任务+进度查询
5. Windows ARM 无法安装 smbprotocol（上游 cryptography 无轮子），待上游跟进
