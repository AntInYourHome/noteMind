# NoteMind 业务流程图

## 1. 总体业务流程

```
用户准备好源文件目录                    配置 config.json
        │                                    │
        ▼                                    ▼
┌──────────────────────────────────────────────────────────┐
│                    import.py 启动                         │
│                                                          │
│  1. 解析 CLI 参数 (--source, --vault, --resume, --dry-run)│
│  2. 加载 config.json                                     │
│  3. 初始化 AI Provider 池 (多 Key + 健康追踪)              │
│  4. 初始化 AgentScheduler (优先级调度)                     │
│  5. 初始化 MemoryStore (SQLite)                           │
│  6. 初始化 MetricsCollector (指标采集)                     │
│  7. 加载去重索引 (.notemind_index.json)                    │
│  8. 加载检查点 (--resume 模式)                             │
│  9. 递归扫描源目录，收集支持格式的文件                       │
│ 10. 过滤已处理文件 (resume 模式)                            │
└──────────────────────┬───────────────────────────────────┘
                       │
                       ▼
            ┌──────────────────────┐
            │  逐文件处理管道        │  ← 循环处理每个文件
            │  handle_file()       │
            └──────────┬───────────┘
                       │
                       ▼
            ┌──────────────────────┐
            │  管道执行完成后        │
            │  update_moc()        │  ← 生成知识树
            │  保存指标报告          │
            │  Provider 健康报告    │
            │  日志分析报告         │
            └──────────────────────┘
```

## 2. handle_file() 逐文件处理管道

这是核心业务流程，每个文件依次经过 8 个阶段：

```
                    输入: file_path (源文件路径)
                              │
                              ▼
                    ┌─────────────────┐
                    │ 阶段 1: 解析     │
                    │ parsers.py      │
                    │                 │
                    │ get_parser()    │── 根据扩展名选择解析器
                    │ parse_xxx()     │── 提取文本、图片、章节
                    │                 │
                    │ 输出: ParseResult │
                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │ 阶段 2: AI 分析  │
                    │ analyzer.py     │
                    │ ai_client.py    │
                    │                 │
                    │ 文档特征判断:    │
                    │  < 3000字符 &    │
                    │  < 3 章节        │── Yes → ShortDocStrategy
                    │                  │        (单摘要 + 单标签)
                    │  >= 3000字符 OR  │
                    │  >= 3 章节       │── Yes → LongDocStrategy
                    │                  │        (逐章摘要 + 逐章标签
                    │                  │         + 图片描述)
                    │                 │
                    │ 有 scheduler?   │── Yes → 批量并发 (ThreadPoolExecutor)
                    │                 │        按优先级: 图片 > 摘要 > 标签
                    │                 │
                    │ 输出: AnalysisResult │
                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │ 阶段 3: 分类     │
                    │ classifier.py   │
                    │                 │
                    │ 取各章摘要前100字│
                    │ + 图片描述前200字│──→ AI 选择预设分类
                    │                 │
                    │ 输出: category   │  (如 "芯片")
                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │ 阶段 4: 归档     │
                    │                 │
                    │ 复制原始文件到   │
                    │ vault/_archive/ │
                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │ 阶段 5: 图片处理 │
                    │                 │
                    │ 复制提取的图片到 │
                    │ .notemind_assets│
                    │ /<文件名>/      │
                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │ 阶段 6: Markdown│
                    │ builder.py      │
                    │                 │
                    │ 判断是否大文档:  │
                    │  章节 >= 5 OR   │
                    │  字符 > 10000   │
                    │                 │
                    │  Yes → 拆分:    │
                    │   索引文件 +     │
                    │   每章独立文件   │
                    │                 │
                    │  No → 单文件:   │
                    │   frontmatter + │
                    │   摘要 + 正文 + │
                    │   图片 + 标签   │
                    │                 │
                    │ 输出: .md 写入   │
                    │ vault/<category>/│
                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │ 阶段 7: 去重更新 │
                    │ dedup.py        │
                    │                 │
                    │ 计算文件 MD5     │
                    │ 写入去重索引     │
                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │ 阶段 8: 记忆存储 │
                    │ memory.py       │
                    │                 │
                    │ INSERT INTO     │
                    │ documents       │
                    │ 更新标签索引     │
                    └─────────────────┘
```

## 3. 大文档自动拆分流程

当文档章节数 ≥ 5 或总字符数 > 10000 时触发：

```
                    输入: AnalysisResult (多章节)
                              │
                              ▼
                    ┌─────────────────────────┐
                    │ 构建章节链接列表         │
                    │ [(link_name, title), ...]│
                    └────────────┬────────────┘
                                 │
                    ┌────────────▼────────────┐
                    │ 写索引文件 (主文档)      │
                    │                         │
                    │ frontmatter:            │
                    │   doc_type: index       │
                    │   sections: N           │
                    │   original_path: ...    │
                    │                         │
                    │ 内容:                    │
                    │   文件摘要 (第一章)      │
                    │   目录 ([[链接]])        │
                    │   页脚                   │
                    │                         │
                    │ 输出: vault/芯片/        │
                    │   2026-04-30-书名.md    │
                    └────────────┬────────────┘
                                 │
                    ┌────────────▼────────────┐
                    │ 循环写每个章节文件       │
                    │                         │
                    │ 每章 frontmatter:       │
                    │   parent: 索引文件名     │
                    │   original_path: ...    │
                    │                         │
                    │ 每章内容:               │
                    │   章节标题              │
                    │   AI 摘要               │
                    │   AI 正文               │
                    │   图片描述              │
                    │   返回链接 [[父文档]]    │
                    │                         │
                    │ 输出: vault/芯片/        │
                    │   2026-04-30-书名-01-章1│
                    │   2026-04-30-书名-02-章2│
                    │   ...                   │
                    └─────────────────────────┘
```

## 4. AI 并发调用流程

```
                    AgentScheduler.analyze_batch()
                    输入: [text1, text2, ...], [img1, img2, ...]
                              │
                              ▼
                    ┌─────────────────────────┐
                    │ 任务分解                 │
                    │                         │
                    │ 文本 → 摘要任务          │
                    │ 文本 → 标签任务          │
                    │ 图片 → 视觉分析任务      │
                    │                         │
                    │ 按优先级排序:            │
                    │   1. image_analysis     │
                    │   2. summary            │
                    │   3. classify           │
                    │   4. tags               │
                    └────────────┬────────────┘
                                 │
                    ┌────────────▼────────────┐
                    │ ThreadPoolExecutor       │
                    │ max_workers = concurrency│
                    │                         │
                    │  ┌───┐ ┌───┐ ┌───┐     │
                    │  │T1 │ │T2 │ │T3 │ ... │ ← 并发执行
                    │  └─┬─┘ └─┬─┘ └─┬─┘     │
                    │    │     │     │        │
                    │    ▼     ▼     ▼        │
                    │  APIProviderPool         │
                    │  ┌─────────────────┐    │
                    │  │ next_provider() │──→ 轮询选 Key
                    │  │ 跳过熔断的 Key  │    │
                    │  │ 记录成功/失败   │    │
                    │  └─────────────────┘    │
                    │    │     │     │        │
                    │    ▼     ▼     ▼        │
                    │  DashScope API           │
                    └────────────┬────────────┘
                                 │
                                 ▼
                    ┌─────────────────────────┐
                    │ 结果聚合                 │
                    │ {"summaries": [...],    │
                    │  "tags": [...],          │
                    │  "image_descs": [...]}   │
                    └─────────────────────────┘
```

## 5. Provider 健康追踪流程

```
                    每次 API 调用后
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
         成功响应         429 限流        其他错误
              │               │               │
              ▼               ▼               ▼
        tracker.record    tracker.record    tracker.record
        _success()        _failure(429)     _failure(err)
              │               │               │
              ▼               ▼               ▼
        重置熔断器        开启 30s 冷却     记录错误
        success_count++   rate_limit++     failure_count++
              │               │
              │               ▼
              │         next_provider()
              │         跳过此 Key
              │         选择下一个可用 Key
              │
              ▼
        导入完成后: print_health_report()
        ┌──────────────────────────────────────┐
        │ Provider 健康报告                     │
        │ ✅ qwen3.6-flash | 评分: 0.95         │
        │    成功: 150 | 失败: 2 | 限流: 1      │
        │ ⛔ qwen3.6-flash | 限流冷却中 (15s)   │
        │    成功: 50  | 失败: 30| 限流: 28     │
        └──────────────────────────────────────┘

        日志分析: analyze_provider_from_logs()
        ┌──────────────────────────────────────┐
        │ Provider 日志分析报告                 │
        │ 🟡 [MEDIUM] API 限流 (429) × 12      │
        │    建议: 减少 concurrency 或增加 Key  │
        │ 🟠 [HIGH] 所有 Provider 同时被限流 × 2│
        │    建议: 必须降低并发数或增加更多 Key │
        └──────────────────────────────────────┘
```

## 6. 检查点恢复流程

```
                    异常中断 / 手动 Ctrl+C
                              │
                              ▼
                    ┌─────────────────────┐
                    │ metrics.save_checkpoint │
                    │ 原子写入 (.tmp + rename)│
                    │                     │
                    │ checkpoint.json:    │
                    │  - source_dir       │
                    │  - all_files[]      │
                    │  - processed_set    │
                    │  - run_id           │
                    └─────────────────────┘

                    用户重新运行: import.py --resume
                              │
                              ▼
                    ┌─────────────────────┐
                    │ MetricsCollector     │
                    │ .load_checkpoint()   │
                    │                     │
                    │ 恢复已处理文件集合   │
                    │ 从 all_files 中过滤  │
                    │ 仅处理剩余文件       │
                    └─────────────────────┘
```

## 7. MOC (知识树) 生成流程

```
                    所有文件处理完成后
                              │
                              ▼
                    ┌─────────────────────────┐
                    │ update_moc(vault_path)  │
                    │                         │
                    │ 遍历每个 category 目录   │
                    │   读取每个 .md 文件     │
                    │   仅读前 500 字符       │ ← 性能优化
                    │   解析 frontmatter      │
                    │   提取 tags (最多3个)    │ ← 性能优化
                    │   跳过 doc_type:index   │ ← 避免重复统计
                    │                         │
                    │ 按标签聚合               │
                    │ 按分类聚合               │
                    └────────────┬────────────┘
                                 │
                                 ▼
                    ┌─────────────────────────┐
                    │ 写入 vault/MOC.md       │
                    │                         │
                    │ # 知识树                │
                    │ ## 芯片 (12 篇笔记)     │
                    │ - [文件名](链接)        │
                    │   `#标签1` `#标签2`     │
                    │ ## 安全 (8 篇笔记)      │
                    │ ...                     │
                    │                         │
                    │ ## 标签云               │
                    │ #RISC-V (5) #安全 (3)   │
                    └─────────────────────────┘
```
