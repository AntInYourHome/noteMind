# NoteMind 推荐分类树设计

## 设计思路

结合业界最佳实践（ISO 27001、等保四级、数据分类分级国标）与个人知识管理方法论（PARA、KG笔记法），采用 **3 级分类树 + 标签云** 的双层结构。

---

## 设计原则

### 1. 3级分类 + 标签（分层策略）

| 层级 | 用途 | 示例 |
|------|------|------|
| **一级**（目录） | 最大领域划分 | `安全`、`操作系统`、`技术`、`个人` |
| **二级**（子目录） | 平台/场景细分 | `HarmonyOS`、`PC安全`、`安全运营` |
| **三级**（子目录） | 具体系统/主题 | `权限模型`、`SELinux策略` |
| **标签** | 文档类型 + 关键词 | `白皮书`、`架构文档`、`漏洞分析` |

### 2. 文件夹 vs 标签分工

| 维度 | 用文件夹 | 用标签 |
|------|---------|--------|
| 分类维度 | ✅ 按平台/系统/领域 | ❌ |
| 文档类型 | ❌ | ✅ `白皮书`、`教程`、`报告`、`笔记` |
| 技术关键词 | ❌ | ✅ `SELinux`、`微内核`、`TEE` |
| 状态 | ❌ | ✅ `草稿`、`已审核`、`已归档` |

### 3. 业界参考

- **ISO 27001**：按"方针 → 制度 → 规程 → 记录"四级文件分层
- **等保2.0**：按"物理 → 网络 → 主机 → 应用 → 数据"分层
- **PARA 方法**：Projects → Areas → Resources → Archives
- **Obsidian 实践**：文件夹粗分 + 标签细分 + 双链关联

## AI 分类策略

1. **一级判断**：先看文档大领域（安全？操作系统？技术？个人？）
2. **二级判断**：在领域内看平台/场景（HarmonyOS？Android？PC？移动？）
3. **三级判断**：具体系统/主题（权限模型？SELinux？架构？）
4. **标签补充**：从文档内容提取文档类型标签（白皮书/教程/报告/笔记）
