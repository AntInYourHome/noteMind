    SECTION 02 · REFERENCE MODEL03 / 09
    统一抽象 · 三域模型

    硬件方案 = 三个域 + 三件套机制

    NS · NORMAL SPHERE（开放域 · 不可信）
    Agent / VLA / 工具
    黑盒意图生成——注入、后门、幻觉是常态而非例外
    意图：tool call / q* ▼▲ 令牌 / q_safe
    SS · SECURE SPHERE（安全域 · 最小 TCB）
    裁决器 + 策略 + 证据链
    NS 杀不掉、写不进、伪造不了其输出
    带签名 / MAC 的命令 ▼
    GATE · 执行边界
    工具执行器 / 电机驱动 / 敏感外设
    只接受 SS 域签名的令牌——强制互连
    i.强制互连
    执行通路在芯片层（TZPC / 外设防火墙）只对 SS 开放——NS 提权再高也物理上够不到执行边界，这是与 OS 权限的本质区别。
    ii.度量锚定
    裁决代码经 secure boot 度量链验证后才运行；策略更新走签名 + 版本化，验证密钥从文件系统移到信任根。
    iii.证据外送
    hash chain 的链头签名密钥锚在硬件，外送通道独立于 NS——NS 全域沦陷时，"发生过什么"仍然可审计。
    安全硬件强制方案推导硬件方案不是替换这条链，而是给裁决与证据两个环节物理地位
    SECTION 03 · L2 PATH04 / 09
    下沉路径 一 · L2

    Prismor 裁决平面的 TEE 化（改造面小）

    现状下沉后增量价值
    eval-server 进程间评估通道→评估服务整体进 CVM / TEE裁决器脱离 NS 权限域
    签名远程策略（密钥在文件系统）→签名验证密钥进 TPM / DICE策略不可被 NS 篡改
    hash chain 自签证据链→链头密钥锚定硬件信任根日志不可删改
    裁决结果 = 返回值→短时效能力令牌（nonce + 过期）裁决执行原子绑定，杀 TOCTOU
    LLM judge 终裁→judge 降级为建议，SS 只复核结构化事实judge 被注入不再致命
    绕过失效检验 拆闸 ✓（NS 碰不到 CVM 内进程） 解析走私 ✓（规范化代码被度量，解析器与工具同源） TOCTOU ✓（令牌一次性 + nonce）
    安全硬件强制方案推导计算可行性：策略评估 µs–ms 级，CVM 可承担；语义评估留 NS 异步

    THE CONVERGENCE INTERFACE · 合流点

    L2 的裁决输出，参数化 L4 的安全集合

    g(q) = g_base(q) ∧ contract(q)
    TEE 裁决产出的任务契约（允许动作集合 / 参数边界）经签名下发到安全岛， 作为投影流形的参数——数字侧判定"这个任务允许碰什么、多大幅度"， 物理侧的安全集合随之收紧。两个项目各自指到了这个接口，中间的通道不存在—— 这是本方案最有原创价值的一格，也是最值得下注的空窗。

    SECTION 05 · PLATFORM MATRIX07 / 09
    选型 · 各安其位

    CVM / 安全岛 / 安全MCU——三个家

    CVMTDX / SEV-SNP / CCA 安全岛AURIX / RH850 / S32K + HSM 安全 MCUTrustZone-M · PSA / SESIP
    适配场景云 / 工作站 agent（L2 为主）车载 / 机器人边缘（L4 实时）端侧轻量 agent、传感节点
    实时性ms 级（VM 切换开销）µs 级 · lockstep · WCET 可认证µs–ms 级

    典型角色策略与证据的家最后的闸门传感器第一跳 / 最小强制点
    选型原则一句话：证据与策略住 CVM，最后的闸门住安全岛，传感器第一跳住安全 MCU——混合部署是车载与具身的标准形态。
    安全硬件强制方案推导SoC 内 TEE 做重计算 + 安全岛做实时终裁
    SECTION 06 · ROADMAP08 / 09
    分阶段落地 · 攻击验证增量

    每一步都有一次拔闸测试

    0PHASE · 纯软件
    现状部署 + 证据锚点
    Prismor + Cudro 原样部署；把 hash chain 链头锚到本机 TPM（改动小）。
    验证物
    日志链可在 NS 域之外独立校验。
    1PHASE · 信任根下沉
    密钥与核的锚定
    策略签名密钥进 TPM / DICE；投影核切 AOT + 签名，脱离 JIT。
    验证物
    NS 域 root 权限下也无法伪造策略 / 替换核。
    2PHASE · 裁决下沉
    裁决器进隔离域
    eval-server 进 CVM（L2）；投影核上 AURIX / S32K EVK 的 lockstep 核（L4）。
    拔闸测试
    杀掉 NS 全部进程，物理动作仍在安全流形内——硬件增量价值的直接判据。
    3PHASE · 强制互连
    完整链闭环
    执行器命令 MAC 鉴权（CAN-FD / ETHERCAT safety），传感器源头认证，TEE→安全岛契约下发通道落地。
    验证物
    从注入到物理伤害的每条路都要过一道硬件闸。
    安全硬件强制方案推导每阶段用「拔掉硬件闸门后攻击是否仍被拦」验证增量
