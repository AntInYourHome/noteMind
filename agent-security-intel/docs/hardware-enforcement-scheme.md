# 安全硬件强制方案推导：从 Prismor 与 Cudro 出发

> 姊妹篇：[Prismor 拆解](prismor-runtime-enforcement.md)（L2 运行时裁决）、[Cudro 拆解](cudro-vla-safety-filter.md)（L4 流形投影）。
> 本文回答一个问题：**结合这两个样本，安全硬件（安全MCU/安全岛/安全芯片）到底怎么做 Agent 安全**。
> 总纲与四层模型见 [unified-map.md](unified-map.md)；主题：硬件作为物理世界与软件之间的安全屏障。

## 0. 两个样本给了两块"半成品答案"

把两篇拆解的结论并排放：

| | Prismor | Cudro |
|---|---|---|
| 管什么 | agent 的数字动作（tool call） | agent 的物理动作（关节指令 q*） |
| 裁决语义 | allow / block / HITL / modify | 投影：q_safe = argmin‖q−q*‖ s.t. g(q)≥0 |
| 已收敛的东西 | canonical event、策略引擎、hash chain + Ed25519 证据链、签名远程策略 | µs 级确定性投影核、声明式可验证约束、AOT/JIT 双后端、差分验证 |
| **共同缺口** | 裁决器与被裁决对象**同权限域**（同 OS、同 uid）——`pkill` / 改策略文件 / 解析走私 / TOCTOU 全部仍然可行 | 投影核跑在应用处理器上，与 VLA 共享 OS——绕过它不需要攻破它，只需要绕开它 |

两块拼起来看得更清楚：**决策逻辑已经"可验证"了（策略可签名、约束可微分验证、日志可链式防篡改），但执行环境的"不可绕过"仍然只是软件互锁**。两个项目各自用密码学把"可证明"做满，把最后一步留给了硬件——这就是方案推导的起点。

## 1. 统一抽象：动作执行的通用链与三个域

无论数字动作还是物理动作，执行链同构：

```
意图生成（不可信：LLM/VLA 黑盒）
   → 意图规范化（canonical event / q* 提案）      ← Prismor/Cudro 各自已做
   → 裁决（策略引擎：allow/block/HITL；
           投影器：q_safe）                        ← 逻辑已可验证
   → 执行（工具执行器 / 电机驱动）
   → 证据（审计日志 / 遥测）
```

硬件强制的目标不是替换这条链，而是给**裁决**与**证据**两个环节物理地位。由此得三域参考模型：

```
┌─────────────────────────────────────────────────┐
│ NS 域（开放域，不可信）                            │
│  agent 运行时 · LLM/VLA 推理 · 工具 · 浏览器       │
│  ——随时可能被注入/后门/幻觉，且这是常态不是例外     │
└──────────────┬──────────────────▲───────────────┘
               │ 意图（canonical event / q*）│ 允许令牌 / q_safe
┌──────────────▼──────────────────┴───────────────┐
│ SS 域（安全域，最小 TCB）                          │
│  裁决器（策略引擎 + 投影核）· 策略 · hash chain 日志│
│  ——NS 杀不掉、写不进、伪造不了其输出               │
└──────────────┬──────────────────────────────────┘
               │ 带签名/MAC 的命令
┌──────────────▼──────────────────────────────────┐
│ 执行边界：工具执行器 / 电机驱动 / 敏感外设          │
│  ——只接受 SS 域签名的令牌（强制互连）              │
└─────────────────────────────────────────────────┘
```

硬件方案 = 三件套机制：

1. **强制互连（enforced interconnect）**：执行器与敏感外设的控制通路在硬件层只对 SS 域开放（TZPC/SAU/外设防火墙配置）。NS 域进程无论提权到什么程度，都物理上够不到执行边界——这是与"软件互锁"的本质区别：后者靠 OS 权限，前者靠芯片配置。
2. **度量锚定（measured anchoring）**：SS 域内的裁决代码（策略引擎/投影核）经 secure boot 度量链验证后才运行；策略更新走签名+版本化——Prismor 的"签名远程策略"直接复用，只是验证密钥从文件系统移到信任根。
3. **证据外送（tamper-evident exfil）**：hash chain 在 SS 域内追加（Prismor 已实现链式结构），**链头签名密钥在硬件信任根**，外送通道独立于 NS 域——NS 被完全攻陷时，"发生过什么"仍然可审计。

## 2. 两条下沉路径

### 2.1 L2 路径：Prismor 的裁决平面 TEE 化

改造点对照（利用其现有接口，改造面小）：

| Prismor 现状 | 下沉后 | 增量价值 |
|---|---|---|
| eval-server（进程间评估通道） | 评估服务整体进 CVM/TEE，event 经该通道入域 | 裁决器脱离 NS 权限域 |
| 签名远程策略（密钥在文件系统） | 策略签名验证密钥进信任根（TPM/DICE） | 策略不可被 NS 篡改 |
| hash chain + Ed25519（自签） | 链头密钥锚定硬件 | 日志不可删改 |
| 裁决结果=返回值 | **短时效能力令牌**（含 nonce + 过期的一次性签名凭证） | 裁决与执行原子绑定，杀 TOCTOU |
| LLM judge 终裁 | judge 留 NS 域，但降级为"建议"；SS 域只复核结构化事实后出终裁 | judge 被注入不再致命 |

此前列的三类绕过逐一失效检验：**拆闸**（NS 进程碰不到 CVM 内进程）✓；**解析走私**（规范化/解析代码在度量过的 SS 域内，裁决器与工具的解析器一致性由同一份被度量代码保证）✓；**TOCTOU**（令牌一次性+nonce，执行器验签后即作废）✓。

计算可行性：策略评估主体是 regex/规则匹配（µs–ms 级），CVM 可承担；偶发的语义评估留在 NS 域异步进行，不阻塞热路径。

### 2.2 L4 路径：Cudro 的投影核进安全岛

利用其已埋好的双后端，关键是**把开发期/部署期分开**：

```
开发期（NS 域）：.cudro 约束迭代 + TCC JIT 快速验证（5-9.5ms 重编译）
        ↓ 约束冻结
部署期：codegen_llvm AOT 固化投影核 → 签名 → 度量 → 装入安全岛
运行期（双域协作）：
  VLA（应用处理器/GPU，NS）──q*──▶ 安全岛（SS）：project(q*) ──q_safe──▶
  电机驱动（只接受带 MAC 的命令帧）
```

为什么这条路成立——Cudro 的形态恰好匹配安全岛的约束：

- **11.6 µs/次、无堆分配、单遍求值**：WCET 可分析，进得去实时域（IEC 61508/ISO 26262 对安全相关软件的确定性要求，JIT 天然不满足、AOT 满足——JIT/认证的矛盾在这条路上自然消解）；
- **岛内 TCB = 投影核+调度+通信栈，数千行量级**：可形式化验证的规模（对比 NS 域 OS+框架的百万行）；
- **fail-safe 语义恰好由安全岛补齐**（Cudro 目前缺失的部分）：投影不收敛/超时 → 输出预定义安全态（保持/缓停），看门狗兜底——lockstep 核+看门狗正是安全岛的传统能力。**算法工程缺的那块板，正好是硬件平台的强项**，这不是巧合：这类算法天生就该住在这样的平台上。

### 2.3 合流点：两域之间的接口（没人做出来的那格）

具身 agent 操纵物理世界时，两个裁决域需要对话：

```
TEE 裁决（L2）：任务契约（允许动作集合/参数边界）
        ↓ 签名下发
安全岛裁决（L4）：契约作为约束流形的参数
        g(q) = g_base(q) ∧ contract(q)
```

即 **L2 的裁决输出参数化 L4 的安全集合**：数字侧判定"这个任务允许碰哪些东西、什么幅度"，物理侧的投影流形随之收紧。两个拆解各自指到了这个接口（Prismor 的 contract.py、Cudro 的 task 声明），但中间的签名下发通道不存在——**这是本方案里最有原创价值的接口，也是最值得下注的空窗**。

## 3. 选型矩阵：安全MCU / 安全岛 / CVM 怎么挑

| | CVM（TDX/SEV-SNP/CCA） | 安全岛（AURIX/RH850/S32K + HSM） | 安全MCU（TrustZone-M，PSA/SESIP） |
|---|---|---|---|
| 适配场景 | 云/工作站 agent（L2 为主） | 车载/机器人边缘（L4 为主，实时） | 端侧轻量 agent、传感器节点 |
| 实时性 | ms 级（VM 切换开销） | **µs 级、lockstep、WCET 可认证** | µs–ms 级 |
| TCB 容量 | 大（可跑完整策略引擎+审计） | 小（数千行，可形式化） | 极小 |
| 外设强制力 | 弱（域边界在内存，不在引脚） | **强（外设防火墙直达执行器）** | 中（TrustZone-M 分区） |
| 认证路径 | CC EAL / 机密计算联盟 | **ISO 26262 ASIL-D / IEC 61508** | PSA Certified / SESIP |
| 典型角色 | 策略与证据的家 | **最后闸门** | 传感器认证/最小强制点 |

选型原则一句话：**证据和策略住 CVM，最后的闸门住安全岛，传感器的第一跳住安全 MCU**。混合部署（SoC 内 TEE 做重计算 + 安全岛做实时终裁）是车载/具身的标准形态。

## 4. 分阶段路线（每一步都可用攻击验证增量）

- **Phase 0（纯软件，现在就能做）**：Prismor+Cudro 原样部署；把证据链头锚到本机 TPM（改动小）。验证物：日志链可独立校验。
- **Phase 1（信任根下沉）**：策略签名密钥进 TPM/DICE；投影核切换 AOT+签名，脱离 JIT。验证物：NS 域 root 下也无法伪造策略/替换核。
- **Phase 2（裁决下沉）**：eval-server 进 CVM（L2）；投影核上安全岛评估板（L4，如 AURIX TC3xx / S32K3 EVK 的 lockstep 核）。验证物：**杀掉 NS 域全部进程，物理动作仍在安全流形内**——这是"拔闸测试"，硬件增量价值的直接判据。
- **Phase 3（强制互连）**：执行器命令加 MAC 鉴权（CAN-FD/ETHERCAT safety profile），传感器源头认证，TEE→安全岛契约下发通道落地。验证物：完整链——从注入到物理伤害的每条路都要过一道硬件闸。

## 5. 开放问题（不装作都解决了）

1. **HITL 的可信路径**：人工审批的 UI 本身在 NS 域，可被注入伪造"已批准"——secure path to human 是四十年老问题，agent 时代更尖锐；
2. **judge 的位置悖论**：LLM judge 留 NS 可被骗，进 SS 则 TCB 膨胀且不可验证——当前折中（judge 仅建议+SS 复核事实）只是缓解；
3. **跨域性能**：每次裁决的域切换开销（VM exit/证明）对 100–1000 Hz 控制环过重——需共享内存+批量裁决，工程上没有免费的闸门；
4. **策略表达力 vs 可验证性**：Prismor 16 类够 L2 起步；L4 约束语言（plane/point/clearance）还承载不了动态场景（速度约束、ḣ 项）；
5. **认证与迭代速度的矛盾**：认证的对象必须是闸门（裁决器/投影核/互连配置），不能是策略内容或模型——契约分层是唯一的路，否则每次改提示词都要重认证。

---

## 6. 结论

两个样本证明的事可以压缩成一句：**Agent 安全的"逻辑层"已经收敛（规范化事件、可签名策略、可验证约束、防篡改日志），收敛到的位置恰好是硬件能接手的位置**。安全硬件方案不是发明新机制，而是给已收敛的逻辑三个物理属性——裁决不可绕过（强制互连）、身份不可伪造（度量锚定）、历史不可篡改（证据外送）。L2 看 CVM，L4 看安全岛，中间的契约下发接口是值得下注的空窗。
